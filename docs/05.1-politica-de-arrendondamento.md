# Política de arredondamento

Utilize:

```text
HALF_UP
2 casas decimais
```

A política deve ser consistente em todo o domínio.

## Regra geral

Não arredonde valores durante cálculos intermediários desnecessariamente.

O cálculo deve preservar a maior precisão possível até o ponto definido como resultado monetário.

### Juros

O cálculo do juros deve ser realizado primeiro com a precisão disponível.

Exemplo:

```text
MULTA
valor_original = 300.50
taxa = 0.01
dias = 85

juros_calculado =
300.50 × 0.01 × 85
= 255.425
```

Somente depois o juros deve ser arredondado:

```text
255.425
   ↓ HALF_UP
255.43
```

O valor atualizado será então:

```text
valor_atualizado =
valor_original + juros_arredondado

300.50 + 255.43
= 555.93
```

### IPVA

Para o IPVA, primeiro calcule o juros e depois aplique o teto:

```text
juros_calculado =
valor_original × 0.0033 × dias_atraso

juros_teto =
valor_original × 0.20

juros_aplicado =
min(juros_calculado, juros_teto)
```

Depois arredonde o `juros_aplicado` para 2 casas usando HALF_UP.

Finalmente:

```text
valor_atualizado =
valor_original + juros_aplicado
```

### Totais

Os totais devem ser calculados a partir dos valores monetários já normalizados para 2 casas:

```text
total_original =
soma dos valores originais

total_atualizado =
soma dos valores atualizados
```

Não utilizar `float`.

### Regra importante

Não realizar múltiplos arredondamentos desnecessários durante uma mesma operação.

A intenção é evitar situações como:

```text
cálculo intermediário
→ arredondamento
→ novo cálculo
→ novo arredondamento
```

quando isso não for exigido pela regra de negócio.

Documente essa política no README e crie testes específicos para os casos de arredondamento HALF_UP.

## Implementação Realizada

### 1. Componentes Criados e Refatorados

1. **`App\Domain\Debt\Rounding\HalfUpRounder`**:
   - Utilitário puro de domínio com aritmética de inteiros exata `round(int $numerator, int $denominator): int`.
   - Implementa `HALF_UP` sem tipos `float`: `intdiv($numerator + intdiv($denominator, 2), $denominator)`.
   - Lança `InvalidArgumentException` se o denominador for menor ou igual a zero.

2. **`App\Domain\Debt\Money`**:
   - Conversão de string decimal (`fromDecimal`) via manipulação estrita de inteiros e strings (`explode('.', $clean)` e preenchimento de centavos com zeros à direita), sem conversão para ponto flutuante binário.
   - Formatação para string decimal (`toDecimal`) puramente com inteiros (`intdiv` e `% 100`).
   - Métodos adicionais: `subtract`, `isZero`, `isPositive`, `isNegative`.

3. **`App\Domain\Debt\Policies\IpvaInterestPolicy`**:
   - Juros e teto de 20% calculados sobre a mesma base fracionária (`10.000`).
   - Teto aplicado antes de qualquer arredondamento: `min($calculatedNumerator, $capNumerator)`.
   - Arredondamento `HALF_UP` executado estritamente sobre o juros aplicado final.

4. **`App\Domain\Debt\Policies\MultaInterestPolicy`**:
   - Juros calculado sem arredondamentos intermediários: `valor_original × 0.01 × dias`.
   - Arredondamento `HALF_UP` executado via `HalfUpRounder` para 2 casas decimais.

5. **`App\Domain\Debt\Services\DebtCalculationService`**:
   - `total_original` e `total_atualizado` calculados diretamente a partir dos valores monetários já normalizados em centavos.

### 2. Testes Implementados

* `Tests\Unit\Domain\Debt\Rounding\HalfUpRounderTest`:
  - Arredondamento `HALF_UP` do exemplo oficial de MULTA (`300.50 * 0.01 * 85 = 255.425 -> 255.43`).
  - Limiares exatos de metade: `.005 -> sobe`, `.0049 -> desce`, `.0051 -> sobe`.
  - Tratamento de números negativos, inteiros puros e rejeição de denominador inválido.
* `Tests\Unit\Domain\Debt\MoneyTest`:
  - Imunidade a armadilhas de precisão binária IEEE-754 (`0.58` parseado estritamente como 58 centavos).
  - Subtração, sinais e formatação de valores negativos.
* `Tests\Unit\Domain\Debt\DebtCalculationServiceTest`:
  - Aplicação do teto de IPVA antes do arredondamento em casos com centavos fracionários (`valor_original = 10.01`).
  - Soma de totais a partir de débitos normalizados sem dispersão por arredondamentos intermediários.
